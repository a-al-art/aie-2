- **Краткое описание (2-4 предложения):** Сервис предсказывает вероятность дефолта (невозврата кредита) по профилю заявителя.
Используется открытый датасет Credit Risk Dataset с Kaggle.
Обучены и сравнены две модели - Logistic Regression (baseline) и CatBoost (финальная).
Результат - REST API на FastAPI: принимает параметры заявки и возвращает оценку риска с вероятностью дефолта.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту.
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  разведочный анализ данных (exp01_eda_baseline.ipynb), сравнение моделей (exp02_model_comparison.ipynb), препроцессинг и новые признаки (exp03_preprocessing_features.ipynb).
- `src/` – основной код проекта. (data/ - загрузка данных, features/ - очистка, feature engineering, препроцессор, models/ - обучение и предсказание, service/ - FastAPI-приложение, utils/ - логгер, загрузчик конфига, train.py - точка входа: обучение, service.py - точка входа: сервис)
- `data/` – исходные (credit_risk_dataset.csv) и обработанные (processed_dataset.csv) данные.
- `configs/` – конфигурационные файлы:
  - `config.yaml`,`.env.example`.
- `tests/` – тесты проекта (pytest)
- `artifacts/` – обученные модели, метрики, графики

## 4. Как запустить проект


### 4.1. Запуск обучения модели

```bash
cd project
python -m src.train
```
После выполнения в `artifacts/` появятся:
- `model.pkl` - обученная модель CatBoost
- `preprocessor.pkl` - препроцессор признаков
- `metrics.json` - метрики обеих моделей (LR и CatBoost)
В `data/` появятся:
- `processed_dataset.csv` - очищенный датасет с новыми признаками

### 4.2. Запуск сервиса (API/веб-интерфейс)

```bash
cd project
python -m src.service
```

Сервис запускается на `http://localhost:5000`.

**Эндпоинты:**

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/health` | Статус сервиса, флаг загрузки модели |
| POST | `/predict` | Оценка риска по профилю заявителя |
| GET | `/docs` | Swagger UI - интерактивная документация |

**Проверка работоспособности:**

Открыть в браузере `http://localhost:5000/docs` - откроется Swagger UI.

Запрос к `/health` должен вернуть:
```json
{"status": "ok", "model_loaded": true}
```

Пример запроса к `/predict` - заявитель с низким риском:
```json
{
  "person_age": 28,
  "person_income": 45000,
  "person_home_ownership": "RENT",
  "person_emp_length": 3.0,
  "loan_intent": "PERSONAL",
  "loan_grade": "B",
  "loan_amnt": 10000,
  "loan_int_rate": 11.5,
  "loan_percent_income": 0.22,
  "cb_person_default_on_file": "N",
  "cb_person_cred_hist_length": 3.0
}
```

Пример ответа:
```json
{
  "loan_status": 0,
  "default_probability": 0.0842,
  "risk_level": "low"
}
```

## 7. Демонстрация на защите

1. **Структура и данные.** Показать папки `src/`, `notebooks/`, `data/`. Датасет содержит 12 признаков профиля заявителя (возраст, доход, стаж, цель кредита, кредитный рейтинг и др.). Целевая переменная - `loan_status` (0/1).

2. **Эксперименты и выбор модели.** Открыть `notebooks/exp02_model_comparison.ipynb` - сравнение Logistic Regression (ROC-AUC 0.88) и CatBoost (ROC-AUC 0.9529). Финальная модель - CatBoost. Показать график сравнения метрик и feature importance.

3. **Сервис.** Запустить `python -m src.service`, открыть `http://localhost:5000/docs`. Отправить два запроса:
   - Заявитель с низким риском (grade B, доход 45000, нет дефолтов в истории) - `risk_level: low`
   - Заявитель с высоким риском (grade G, доход 18000, дефолт в истории) - `risk_level: high`
