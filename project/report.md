Используется открытый датасет Credit Risk Dataset с Kaggle.

## 2. Постановка задачи и контекст

Опишите:

1. **Предметную область и задачу:**
   - Банк или микрофинансовая организация хочет автоматически оценивать риск невозврата при рассмотрении кредитной заявки. Кредитный аналитик или автоматическая система вводит профиль заявителя и получает оценку риска с вероятностью дефолта (не выплаты).

2. **Формулировку задачи в терминах ML/ИИ:**
   - **Тип задачи:** бинарная классификация
   - **Вход:** 11 признаков профиля заявителя - возраст, доход, тип владения жильём, стаж работы, цель кредита, кредитный рейтинг, сумма кредита, процентная ставка, доля кредита от дохода, наличие дефолта в истории, длина кредитной истории
   - **Выход:** `loan_status` - вероятность дефолта [0..1]
   - **Требования:** высокий Recall (важно не пропустить реальный дефолт), достаточная скорость инференса для онлайн-запросов

3. **Целевые метрики качества:**
   -  ROC-AUC - основная, отражает качество ранжирования по риску независимо от порога
   - F1-score - баланс точности и полноты на несбалансированных данных
   - Recall - ключевая для бизнеса - минимизируем число пропущенных дефолтов

## 4. Модели и подходы

Опишите, какие модели вы пробовали и как развивался ваш подход:

1. **Базовые (baseline) модели:** Logistic Regression
- Логистическая регрессия с `class_weight='balanced'` на всём наборе признаков (исходных + engineered). Простая и интерпретируемая модель, даёт адекватный базовый уровень. Параметры: C=1.0, max_iter=1000

2. **Улучшенные модели и эксперименты:** CatBoost
- Градиентный бустинг на деревьях. Хорошо работает с табличными данными, нативно обрабатывает категориальные признаки, устойчив к дисбалансу классов через `class_weights`. Параметры: iterations=500, learning_rate=0.05, depth=6, l2_leaf_reg=3

- Оба подхода обучаются на данных после SMOTE, оцениваются на отложенной тестовой выборке (20%). Подробный код экспериментов - в `notebooks/exp02_model_comparison.ipynb`

## 5. Экспериментальный протокол и результаты

Здесь важно показать, что выбор финальной модели был осмысленным.

1. **Экспериментальный протокол:**
   - Train / Test: 80% / 20%, по `loan_status`
   - Кросс-валидация финальной модели: StratifiedKFold, 5 фолдов

2. **Сравнение моделей по метрикам:**

| Модель | ROC-AUC | F1 | Precision | Recall | Accuracy |
|--------|---------|----|-----------|--------|----------|
| Logistic Regression (baseline) | 0.8800 | 0.6528 | 0.5606 | 0.7812 | 0.8205 |
| **CatBoost (финальная модель)** | **0.9529** | **0.8368** | **0.9009** | **0.7812** | **0.9342** |

CatBoost, кросс-валидация (CV=5): ROC-AUC = 0.9468 +- 0.0040

3. **Выбор финальной модели:**
Финальная модель - **CatBoost**. Обоснование:

- ROC-AUC выше (0.9529 против 0.8800) - модель значительно лучше ранжирует заявителей по риску
- F1-score выше (0.8368 против 0.6528) - существенно лучший баланс точности и полноты
- Precision выше (0.9009 против 0.5606) - среди помеченных как «дефолт» CatBoost ошибается значительно реже
- **Высокий Recall критически важен: пропущенный дефолт дороже ложной тревоги** - оба показывают 0.7812, но у CatBoost это сочетается с гораздо более высокой точностью
- Устойчивость подтверждена кросс-валидацией: низкая дисперсия (+-0.004)

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
```
credit_risk_dataset.csv
   -clean_data() - удаление дубликатов, выбросов, заполнение пропусков
   -add_features() - feature engineering: 10 новых признаков
   -save_processed() - сохранение в data/processed_dataset.csv
   -ColumnTransformer - StandardScaler + OneHotEncoder
   -SMOTE - балансировка обучающей выборки
   -CatBoostClassifier.fit()
   -joblib.dump() - artifacts/model.pkl, artifacts/preprocessor.pkl
    
запрос к /predict
    -ApplicantFeatures (Pydantic validation)
    -preprocessor.transform()
    -model.predict_proba()
    -{"loan_status", "default_probability", "risk_level"}
```

2. **API и endpoints:**

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/health` | Статус сервиса + флаг `model_loaded` |
| POST | `/predict` | Принимает JSON профиля, возвращает `loan_status`, `default_probability`, `risk_level` |
| GET | `/docs` | Swagger UI |

3. **Технологический стек:**
- **ML:** scikit-learn, CatBoost, imbalanced-learn
- **Сервис:** FastAPI, Uvicorn, Pydantic v2
- **Конфигурация:** YAML + python-dotenv

Запуск:
```bash
python -m src.train    # обучение
python -m src.service  # сервис на localhost:5000
```

## 7. Наблюдаемость, конфигурация и безопасность

Кратко опишите:

1. **Логи и наблюдаемость:**
Структурированные консольные логи через `src/utils/logger.py` (формат: `время | уровень | модуль | сообщение`). В проекте нет секретов и внешних API. Файл `configs/.env.example` пустой: никаких токенов и паролей в проекте не используется. Файл `.env` добавлен в `.gitignore`
